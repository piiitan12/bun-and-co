# コード説明（BUN & CO.）

実案件（2025年5〜10月／クラフトバーガー店）の WordPress 専用テーマを、Next.js（App Router）＋ TypeScript ＋ SCSS Modules で組み直した版のコードの読み方。部品ごとの分け方の理由は [`設計の意図.md`](設計の意図.md)、ページと機能の一覧は [`仕様書.md`](仕様書.md)。

実装には Claude Code を併用。設計（コンポーネント分割・データ分離の方針）と全コードの確認・判断は本人が行った。

---

## 1. WordPress との対応（まずここから）

| WordPress 版 | この版 | ひとことで |
|---|---|---|
| `header.php` / `footer.php` | `src/app/layout.tsx` ＋ `components/layout/Header.tsx` `Footer.tsx` | 全ページ共通の枠。`layout.tsx` が `get_header()`／`get_footer()` の役 |
| `front-page.php` `page-menu.php` など | `src/app/page.tsx`、`src/app/menu/page.tsx` … | **フォルダ名がそのまま URL**（`app/menu/page.tsx` → `/menu`）。テンプレート階層の代わり |
| `404.php` | `src/app/not-found.tsx` | 存在しない URL で自動的に出る |
| `template-parts/` | `src/components/` | 部品。使う範囲でフォルダを分けた（下の 2） |
| 管理画面のメニュー・投稿・カスタムフィールド | `src/data/*.json` | 文言・商品・ナビ。**JSON を直せば表示が変わる** |
| `style.css` と CSS 6 本 | 部品ごとの `*.module.scss` ＋ `src/styles/` | CSS は部品と 1 対 1。共通の色・余白・ブレークポイントは `src/styles/` に 1 か所 |
| `script.js`（jQuery） | 各部品の `useState`・`useEffect` と CSS | jQuery なし。状態か、ブラウザの機能（画面に入ったかの検知・`<dialog>` など）やクリックの処理を持つ部品だけ JavaScript を持つ |
| プラグイン（Instagram Feed・Contact Form 7） | `news.json` の静的な投稿／`ContactForm.tsx` | 外部 API・送信先は持たない（架空の店のため） |
| `wp_head` の meta | 各 `page.tsx` の `metadata` | タイトル・説明文はページごと。OGP と noindex は `layout.tsx` で全体に |

用語
- **コンポーネント（部品）**：見た目と動きをひとまとめにした関数。`template-parts` に近いが、引数（props）を受け取れる
- **サーバーコンポーネント／クライアントコンポーネント**：先頭に `"use client"` があるものだけがブラウザで動く。ないものはサーバーで HTML になって届く
- **型（TypeScript）**：`src/types/data.ts`。JSON に「入れてよい形」の約束。違う形のデータを入れると開発中にエラーで分かる

## 2. フォルダの分け方

```
src/
  app/          ページ（TOP・MENU・GOODS・CONTACT・PRIVACY POLICY・404）と全体の枠
  components/
    layout/     全ページ共通（Header・DrawerNav・Footer・PageTop）
    common/     2 ページ以上で使う小さな部品（Logo・StoreInfo・SectionTitle・Icon・FadeIn・ExternalLink・DummyNotice）
    home/ menu/ goods/ contact/   そのページの部品
  data/         文言・商品・店舗情報（JSON）
  styles/       色・余白・文字の段階の変数（_variables.scss）と mixin（_mixins.scss）
  types/        データの型（data.ts）
```

**なぜ**：「どこで使うか」で置き場を決めたので、部品を直すときに影響する範囲がフォルダ名で分かる。例外は `MenuCard`・`ProductModal`。MENU の部品だが、トップと GOODS でも同じものを使う（見た目をずらさないため）。

## 3. 要所ごとの説明

### 3-1. データ分離（`src/data/*.json` と `src/types/data.ts`）
- **何をしているか**：店名・住所・営業時間（`store.json`）、メニュー（`menu.json`）、グッズ（`goods.json`）、ナビ（`nav.json`）、投稿（`news.json`）、メインビジュアル（`hero.json`）、写真の帯（`gallery.json`）、プライバシーポリシー（`privacy.json`）を JSON に置き、部品はそれを読んで表示するだけ
- **なぜ**：文言と商品はコードより先に変わる。WordPress 版では文言が PHP に直書きで、直すたびにテンプレートを触る必要があった。いまはバーガーを 1 品足すなら `menu.json` の `burgers` に 1 件足すだけで、カードと詳細モーダルが増える
- **型**：`MenuItem`（id・name・price・description・image・options）など。`GoodsItem` は `MenuItem` と同じ形にしたので、グッズのカードとモーダルを作り分けずに済んだ
- **例**：店名を変えるときは `store.json` の `name`・`nameShort`・`copyright` の 3 つ。ロゴの店名・ページのタイトル・コピーライトがそろって変わる。紹介文（`store.json` の `about`・`description`）、グッズの説明（`goods.json`）、プライバシーポリシー（`privacy.json`）の文中の店名は別に直す

### 3-2. 全体の枠（`src/app/layout.tsx`）
- **何をしているか**：全ページ共通で `Header`・`<main id="main">`・`Footer`・`PageTop`・`DummyNotice` を並べる。Google フォント 3 書体（Noto Sans JP・Oswald・Space Grotesk）を `next/font` で読む。サイト全体の `metadata`（タイトルの型・説明文・OGP・検索に出さない設定）もここ
- **なぜ**：WordPress の `header.php`／`footer.php` を毎ページ呼ぶのと同じことを 1 か所で済ませる
- **小さな工夫**：`<body>` の先頭で `html` に `js` クラスを付ける 1 行の script。スクロールで現れる動き（`FadeIn`）は、この印があるときだけ要素を隠す。JavaScript が動かない環境では最初から全部見える

### 3-3. ヘッダーとドロワー（`components/layout/Header.tsx`・`DrawerNav.tsx`）
- **状態を 2 つ持つ**：`open`（ドロワーの開閉）と `scrolled`（200px スクロールしたか）。だからクライアントコンポーネント
- `scrolled` が true になると、`Logo` にマークから店名の文字への切り替えを伝え、ヘッダーを半透明にする（元テーマの `script.js` の threshold = 200 と同じ）
- ドロワーを開いている間は `body` のスクロールを止める
- ハンバーガーは `<button>` に `aria-expanded`・`aria-controls`・開閉で変わる `aria-label` を付けた
- `DrawerNav` は Header と**同じナビのデータ**を受け取って表示するだけ。メニュー項目を 2 か所に書かない

### 3-4. 商品カードと詳細モーダル（`components/menu/MenuCard.tsx`・`ProductModal.tsx`・`MenuList.tsx`）
- **分け方**：カードは押されたことを親に知らせるだけ（`onSelect`）。「いま開いている商品」の状態は親（MENU なら `MenuList`、GOODS なら `GoodsList`、トップなら `MenuPreview`）が 1 つだけ持つ
- **モーダル**：HTML 標準の `<dialog>` を使い、`showModal()`／`close()` で開閉。Esc キーと背景クリックで閉じる。フォーカスの移動はブラウザに任せる
- **なぜ**：元テーマは `footer.php` に空の枠を 1 つ置いて jQuery で中身を書き換えていた。`<dialog>` ならライブラリなしで、閉じ方とフォーカスの扱いが標準どおりになる
- MENU のカテゴリは `menu.json` の `layout` で表示を切り替える：`card`＝写真つきカード（バーガー・サイド）、`list`＝名前と価格だけの表 `PriceTable`（ドリンク・フロート・アルコール）。カテゴリを足すと見出し・ページ内リンク・一覧がそろって増える

### 3-5. BGM（`components/home/BgmToggle.tsx`）
- **何をしているか**：`<audio loop>` の再生と停止をボタン 1 つで切り替える。トップだけ、左下に固定
- **なぜ部品を分けたか**：状態を持つのはこのボタンだけ。ABOUT 全体をクライアントコンポーネントにせず、ここだけ切り出した
- 再生がブラウザに止められた場合（自動再生の制限）は、表示を「停止」に戻す。`aria-pressed` で再生中かどうかを読み上げにも伝える。音源は `preload="none"` で、押すまで読み込まない

### 3-6. お問い合わせフォーム（`components/contact/ContactForm.tsx`）
- **状態を 2 つ持つ**：入力エラーの一覧と、送信済みかどうか
- **確認する内容**：お名前・メールアドレス（形式も）・お問い合わせ内容は必須、電話番号は任意（入れたら数字とハイフン 10〜13 文字）、プライバシーポリシーへの同意は必須
- エラーは欄の下に出し、`aria-invalid` と `aria-describedby` で読み上げにも伝える。送信を押したら、最初にエラーがある欄へフォーカスを移す
- 入力欄に `type`・`inputMode`・`autoComplete` を付け、スマホでメール・電話用のキーボードに切り替わる
- **送信先は持たない**：架空の店なので、送信後は「作品のため実際には送信されない」と表示する。実際に使うなら `onSubmit` の中を送信処理に差し替える（元テーマは Contact Form 7）

### 3-7. スクロールで現れる動き（`components/common/FadeIn.tsx`）
- **何をしているか**：画面に入ったら下からふわっと表示する。`IntersectionObserver`（要素が画面に入ったかをブラウザが知らせてくれる標準の仕組み）を使う
- 表示したら観測をやめる（1 回だけ）。最初から画面内にあるものは待たずに表示する
- **なぜ**：元テーマの jQuery の fade を、ライブラリなしで置き換えた。隠すのは JavaScript が動くときだけ（3-2 の `js` クラス）なので、検索エンジンや JS なしの環境でも中身が消えない

### 3-8. ダミーのリンク（`components/common/ExternalLink.tsx`・`DummyNotice.tsx`）
- Instagram・LINE・Uber Eats は架空の店なので URL が `#`。そのまま押すとページの先頭へ飛んで壊れて見えるため、押してもページは動かさず、画面の下に「架空の店のため、リンク先はありません」と 2.5 秒出す
- `ExternalLink` が合図（`dummy-link` という名前のイベント）を出し、`layout.tsx` に 1 つだけ置いた `DummyNotice` が受け取って表示する。`role="status"` で読み上げにも伝わる
- `store.json`／`nav.json` に本物の URL を入れれば、`target="_blank"` と `rel="noopener noreferrer"` 付きの普通のリンクになる

### 3-9. 404（`src/app/not-found.tsx`）
- 元テーマの `404.php` は「404」と出すだけだった。迷った人が次に進めるよう、案内文・トップへのボタン・主なページへのリンクを置いた
- リンクは `nav.json` のグローバルナビから TOP を除いたもの。ナビを直せば 404 のリンクもそろう
- `robots: { index: false }` で検索エンジンに載せない

### 3-10. タイトル・説明文・OGP・検索に出さない設定
- `layout.tsx` の `metadata`：タイトルの型（`%s｜店名`）、説明文、OGP（画像 `/images/ogp.png`・1200×630）、`robots: { index: false, follow: false }`
- 各ページの `metadata`：そのページのタイトルと説明文。店名は `store.json` から差し込む
- `next.config.ts`：全ページの応答ヘッダーに `X-Robots-Tag: noindex, nofollow`（画像などページ以外のファイルも検索に出さない）と、セキュリティ用のヘッダー 4 つ（ファイルの種類を推測させない・他サイトの枠に入れさせない・参照元を最小限に・カメラ等を止める）
- **なぜ**：架空の店の作品なので、実在の店と間違われないよう検索結果に出さない。URL を渡して見てもらう前提
- OGP 画像の絶対 URL には環境変数 `NEXT_PUBLIC_SITE_URL`（公開 URL）を使う。未指定なら `http://localhost:3000`

### 3-11. スタイルの土台（`src/styles/_variables.scss`・`_mixins.scss`）
- 色（金を 3 段に分けた：黒地の文字＝`$color-gold`、下線・ボタン＝`$color-gold-deep`、白地の文字＝`$color-accent`）、余白の段階（`$sp-1` 4px〜`$sp-12` 240px）、文字の大きさの段階（`$fs-xs` 12px〜`$fs-3xl` 44px）、ブレークポイント（`$bp-tablet: 768px`・`$bp-pc: 1024px`）
- mixin：`tablet`（768px 以上）・`pc`（1024px 以上）・`sp`（767px 以下）、`inner`（内側の幅と左右の余白）、`heading-en`（英字見出し）、`heading-rule`（MENU と GOODS の一覧見出し）、`button-gold` など
- **なぜ**：目分量の値が増えると見た目がばらつく。値を段階に寄せ、使う側は変数名で指定する。SP ファーストで書き、広い画面の指定を mixin で足す

### 3-12. 動き（CSS だけで作ったもの）
- メインビジュアル（`Hero`）：6 枚の写真が順にフェード。CSS アニメーションだけで、遅延は枚数から計算する（`hero.json` の枚数を変えても直す場所がない）
- 写真の帯（`PhotoLoop`）：同じ並びを 2 回つなげて半分だけ動かすので、継ぎ目が出ない
- 見出しの下線：`animation-timeline: view()`（スクロール量に合わせて動かす CSS の仕組み）。未対応のブラウザでは表示時に 1 回のびる
- 動きを減らす設定（`prefers-reduced-motion`）では、写真のフェード・流れる帯・BGM ボタンの鼓動・スクロールでの出現・見出しの下線などの動きを止める（各部品の `*.module.scss` に指定）

### 3-13. 開発用のスクリプト（`scripts/`）
- `screenshot.mjs`：本番ビルドを起動し、Chrome を操作して 375px（モバイルの端末エミュレーション）と 1440px で撮る。撮った画像は `docs/screenshots/`
- `art/map.html`・`art/ogp.html`：ACCESS の案内図と OGP 画像の元の HTML。架空の店なので、実在の地図は使わない

## 4. 面接で聞かれたときの短い答え

| 聞かれそうなこと | 答えの芯 |
|---|---|
| なぜ React で作り直したのか | WordPress の専用テーマで作った実案件を、同じ構成で React に組み直した。同じものを別の道具で作り直すと、設計のどこが道具に依存していて、どこが自分の判断だったかが分かる。WordPress と React の両方で書けることを 1 つの題材で見せられる |
| WordPress との違いは | テンプレート階層の代わりにフォルダ＝URL。管理画面の代わりに JSON。jQuery の代わりに標準 API（`<dialog>`・IntersectionObserver）と CSS |
| 状態はどこで持っているか | ヘッダー（ドロワー・スクロール）、PAGE TOP、モーダルを開く親（MENU・GOODS・トップのメニュー）、BGM、フォーム、ダミーリンクの案内。状態か、ブラウザの機能（画面に入ったかの検知・`<dialog>` など）やクリックの処理を持つ部品だけを `"use client"` にし、それ以外はサーバーで HTML にする |
| 商品を足すには | `menu.json` に 1 件足して、画像を `public/images/burgers/` に置く |
| AI はどう使ったか | 実装に Claude Code を併用。設計の方針と全コードの確認・判断は自分 |
