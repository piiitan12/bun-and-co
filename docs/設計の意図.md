# 設計の意図

このリポジトリのコンポーネントの分け方と、その理由をまとめた文書。ページを実装するたびに追記する。

## 全体の方針

- **データは `src/data/*.json` に寄せる。** 文言・商品・営業時間・ナビはコードより先に変わる。JSON を直せばコードを触らずに差し替えられるようにした
- **1 コンポーネント 1 SCSS Module。** 消していい CSS がすぐ分かるようにする。共通の変数（色・幅・ブレークポイント）と mixin は `src/styles/` に 1 か所
- **状態を持つものだけクライアントコンポーネントにする。** それ以外はサーバーコンポーネントのまま（HTML が軽く、JavaScript が減る）
- **外部ライブラリを増やさない。** ハンバーガー・モーダル・スクロール出現は標準 API（useState・IntersectionObserver）で足りる
- **画像は `public/images/<用途>/` に置き、用途が分かるファイル名にする。** 写真を差し替えるときに迷わない

## 骨組み（ステップ 1）

| 部品 | 置き場 | 分けた理由 |
|---|---|---|
| `Header` | `components/layout/` | ロゴ・ナビ・ハンバーガーボタンをまとめる。ドロワーの開閉と「200px スクロールしたか」の 2 つの状態を持つのでクライアントコンポーネント |
| `DrawerNav` | `components/layout/` | SP 用ドロワー。Header と**同じ nav データ**を受け取るだけの表示部品にし、メニュー項目を 2 か所に書かない |
| `Footer` | `components/layout/` | ロゴ・店舗情報・フッターメニュー・SNS。店舗情報は `StoreInfo` を呼ぶだけ |
| `PageTop` | `components/layout/` | 先頭へ戻るボタン。スクロール量を見て表示するので状態を持つ |
| `Logo` | `components/common/` | ヘッダー用（マーク＋小さな店名。スクロールで店名の文字に切り替わる）とフッター用（店名の文字）。マークは元のロゴから店名の文字だけを外した SVG |
| `StoreInfo` | `components/common/` | 住所・電話・営業時間・定休日。フッターと ACCESS の 2 か所で同じものを出すため共通化。`store.json` を表示するだけ |
| `SectionTitle` | `components/common/` | 英字見出し＋日本語の添え字。見出しレベル（h1／h2）を props で切り替えられるようにし、ページごとに見出しの階層を守る |

### データの分け方

| ファイル | 中身 | なぜ分けたか |
|---|---|---|
| `store.json` | 店名・紹介文・住所・電話・営業時間・SNS・コピーライト | 店舗情報は複数ページで使う。1 か所に置く |
| `nav.json` | グローバル／フッター／SNS のメニュー | WordPress 版ではメニューが DB に 3 つあった。同じ構造を JSON に写した |
| `menu.json` | セクション（BURGERS〜ALCOHOL）→ 商品 | 写真つきのカード（`card`）と名前＋価格だけの表（`list`）を `layout` で切り替える |
| `goods.json` `news.json` `hero.json` `privacy.json` | グッズ・投稿・MV 画像・プライバシーポリシー | ページ単位で差し替えられるように分けた |

### ブレークポイント

元の WordPress 版は SP／PC の 2 段構え（`responsive.css`）。ここでは 768px（タブレット以上）と 1024px（PC 以上）の 2 つを mixin にし、SP ファーストで書く。

## トップページ（ステップ 2）

| 部品 | 置き場 | 分けた理由 |
|---|---|---|
| `Hero` | `components/home/` | 6 枚の写真が順にフェードするメインビジュアル。元テーマは jQuery でクラスを付け替えていたが、**CSS アニメーションだけ**で同じ動きになるので JS を持たない。`hero.json` の枚数が変わっても `animation-delay` を枚数から計算するので直す場所はない |
| `About` | `components/home/` | 店名・紹介文・写真。文章は `store.json` の `about` 配列から出すので、段落の増減はデータだけで済む |
| `BgmToggle` | `components/home/` | `<audio loop>` の再生／停止。状態を持つのはここだけなので、About から切り出してクライアントコンポーネントを最小にした。音源は `src` 1 つで差し替えられる |
| `MenuPreview` | `components/home/` | トップに出すバーガー 4 品。`menu.json` の `burgers` から先頭 4 件を取るだけで、MENU ページと**同じ `MenuCard` と `ProductModal`** を使う（トップとメニューで見た目がずれない） |
| `MenuCard` | `components/menu/` | 写真・名前・価格・説明のカード。クリック時の処理（`onSelect`）は親から受け取り、カード自身はモーダルを知らない。トップでも MENU ページでも同じ部品 |
| `ProductModal` | `components/menu/` | 商品の詳細モーダル。元テーマは `footer.php` に空の枠を 1 つ置いて jQuery で中身を書き換えていた。ここでは `<dialog>` を使い、Esc と背景クリックで閉じる（フォーカスの移動はブラウザに任せる） |
| `News` | `components/home/` | 投稿のグリッド。**元は Instagram Feed プラグインのショートコード。再構成版は `news.json` からの静的モック**で、API キーを持たない。キャプションは hover／フォーカスで出し、タッチ端末では常時表示 |
| `Access` | `components/home/` | `StoreInfo`（フッターと共用）＋案内図の画像＋外部導線（Uber Eats／LINE）。架空の店なので地図は埋め込まず、`scripts/art/map.html` から作った案内図を置いた |
| `FadeIn` | `components/common/` | スクロールで現れる共通の動き。元 `script.js` の fade（jQuery）を `IntersectionObserver` で置き換え。**JS が動く環境（`html.js`）でだけ要素を隠す**ので、JS なし・検索エンジンには最初から見える。マウント時に画面内にあるものは観測を待たずに表示 |

### 実装中に直した崩れ（記録）
- **グリッドの列が画像の固有幅で広がる**：`1fr` は `minmax(auto, 1fr)` で、`next/image` の `width` 属性（800〜1600px）が最小幅になっていた。列を `minmax(0, 1fr)` にして解消
- **閉じたドロワーが横幅を広げる**：`translateX(100%)` で画面外へ出すと `scrollWidth` が 2 倍になり、SP で横スクロールが出る。閉じているときは縦に少しずらして `visibility: hidden` にし、横方向には動かさない
- **スクリーンショットの撮り方**：ヘッドレス Chrome の `--window-size=375` はウィンドウの最小幅（約 500px）に負けて右が切れる。`scripts/screenshot.mjs` は DevTools プロトコルで端末エミュレーション（375px・モバイル）をかけて撮る

## MENU ページ（ステップ 2-2）

| 部品 | 置き場 | 分けた理由 |
|---|---|---|
| `MenuList` | `components/menu/` | ページの本体。カテゴリへのページ内リンクと、モーダルの「いま開いている商品」の状態をここで 1 つだけ持つ。状態を持つのはこの部品だけ |
| `MenuSection` | `components/menu/` | 見出し＋商品一覧。`menu.json` の `layout` が `card` なら写真つきカード、`list` なら名前と価格の表に切り替える。**カテゴリを足すときは JSON に 1 件足すだけ**で、見出し・ジャンプリンク・一覧がそろって増える |
| `PriceTable` | `components/menu/` | 写真のない品（ドリンク・フロート・アルコール）の表。名前と価格を点線でつなぐ。元テーマでは同じ構造を 3 回 HTML で書いていた |
| `MenuCard` `ProductModal` | `components/menu/` | トップページと**同じ部品**を使う。トップで直せば MENU も直る |

- 見出しは h1（MENU）→ h2（BURGERS など）の順。カテゴリの `section` には `aria-labelledby` を付け、`scroll-margin-top` で固定ヘッダーの下に隠れないようにした
- カードの出現は 3 列単位で少しずつ遅らせる（`delay = (i % 3) * 80ms`）。列をまたいで遅れが積み上がらないようにするため

## GOODS ページ（ステップ 2-3）

| 部品 | 置き場 | 分けた理由 |
|---|---|---|
| `GoodsList` | `components/goods/` | LINEUP の見出し・グッズの一覧・モーダルをまとめる。状態は「いま開いている品」1 つだけで、持つのはこの部品だけ |
| `MenuCard` `ProductModal` | `components/menu/` | **MENU と同じ部品をそのまま使う。**グッズのデータ（`GoodsItem`）は商品（`MenuItem`）と同じ形なので、カードもモーダルも作り分けない。元テーマも GOODS は MENU と同じカード・同じモーダルを HTML で複製していた |

- 紹介文と注意書きは `goods.json` の `intro`・`note` から出す。グッズを足すときは `items` に 1 件足すだけ
- 元テーマでは、1 つの品の価格を「モーダル用の `data-price`」と「表示用の本文」の 2 か所に書いていて、**片方だけ直された結果、同じ品に 2 つの価格が出ていた。**再構成版はデータを `goods.json` の 1 か所にし、カードとモーダルは同じ値を読むので、ずれようがない
- MENU のカテゴリ見出しと GOODS の LINEUP は同じ見た目なので、指定を mixin（`heading-rule`）に移して共用した。MENU のスクリーンショットが移す前と同じであることを確認済み

## 元テーマのこだわりの再現（ステップ 2-4）

元テーマで手をかけていた見た目と動きを、jQuery と外部の読み込みを使わずに置き換えた。

| 元テーマ | 再構成版 | 置き換えの方法 |
|---|---|---|
| 黒×金の配色（ヘッダー黒・文字金、見出しの下線とボタンは濃い金） | 同じ配色。本文の地だけ読みやすさのため白〜生成り | 金を 3 段の変数に分けた（黒地の文字＝`gold`、下線・ボタン＝`gold-deep`、白地の文字＝`accent`。白地でも読める濃さ） |
| ロゴ（猫・王冠・バーガー・牛＋店名） | マークはそのまま、店名だけ架空の名前に | SVG から店名のパスのグループだけを外し、店名は Web フォントの文字で添える。名前の変更は `store.json` だけ |
| 200px スクロールでロゴ画像が消え、店名の文字が白く光って現れる。ヘッダーは半透明に | 同じ | `Header` がスクロール量を見て `swapped` を `Logo` に渡す。切り替えは CSS の opacity の遷移 |
| 配達アイコン：ホバーで 1.4 倍・緑の光・下に「Uber Eats」の文字 | 同じ | CSS の `:hover` と `:focus-visible`。キーボードで選んだときも同じ動きになる |
| SNS（フッター）：アイコン＋文字、金→白へ 0.8 秒 | 同じ | アイコンは自作の SVG 部品 `Icon`。`currentColor` なので文字と一緒に色が変わる |
| 店舗情報の 4 つのアイコン（場所・電話・時計・カレンダー） | 同じ | `Icon` を `StoreInfo` の見出しに。フッターと ACCESS の両方に出る |
| 見出しの下線がスクロール量に合わせてのびる（jQuery で毎回計算） | 同じ動き | CSS の scroll-driven animation（`animation-timeline: view()`）。JS なし。未対応のブラウザでは表示時に 1 回のびる |
| 写真が横に流れ続ける帯（90 秒で 1 周） | 同じ | `PhotoLoop`。同じ並びを 2 回つなげて半分だけ動かすので継ぎ目が出ない。写真の一覧は `gallery.json` |
| メインビジュアル：開店年月＋GRAND OPEN!、左に斜めの影 | 同じ | 斜めの影は `clip-path`。店名は見出し（h1）として読み上げ用に残す |
| BGM ボタン：左下に固定、再生中は鼓動のように拡大・縮小 | 同じ | `BgmToggle` をトップだけに置く。鼓動は CSS の `@keyframes` |
| PAGE TOP：ロゴの札＋光る文字、150px スクロールで下からせり上がる | 同じ | 文字は札の中に入れた（生成りの地では白い文字が読めないため） |
| VIEW MORE：ホバーで明るい金が左から右へ満ちる | 同じ。トップの VIEW ALL MENU にも使う | mixin `button-gold` |

- 動きを減らす設定（`prefers-reduced-motion`）のときは、流れる帯・鼓動・ホバーの拡大を止める
- 元テーマにあった LINE の QR コードは、実在のアカウントのものなので入れていない

## 仕上げの見直し（ステップ 2-5）

SP 375px と PC 1440px の全ページを撮り、品質の判定表（余白の体系・タイポのスケール・量産に見えない・SP で重ならない）に当てて直した。撮影は `scripts/screenshot.mjs`（375／1440）。

| 見つけたこと | 直し方 | 結果 |
|---|---|---|
| 余白の値が 22 種類に散らばっていた（5・6・10・14・18・28・30・40・56px など目分量の値） | 8 の倍数を基本にした 10 段（`$sp-1`〜`$sp-10`）を `_variables.scss` に置き、全ファイルを最も近い段に寄せた | 10 段＋細線用の 1〜2px だけ |
| 文字の大きさが 16 種類 | 8 段（`$fs-xs`〜`$fs-3xl`）に寄せた。メインビジュアルの大見出しだけ `clamp()` | 8 段 |
| 写真・カード・地図・ボタンに 4／6／8px と丸いボタンが混在。全部が角丸で量産品に見えた | 写真・カード・地図・価格表は直角。角丸はボタンと札の 2px（`$radius-sm`）だけ。モーダルの閉じるボタンの丸だけ例外 | 2px と 50% の 2 種 |
| カードに影、カードの高さが説明文の長さでばらつく | 影を外し、地色の差（生成りの上の白）で面を分けた。カードを `height: 100%` にして行ごとにそろえた。ボタン要素の中身が上下中央に寄るので、縦並びの flex にして上詰めにした | 行の高さがそろう |
| セクションの地色の並びが不規則（白・白が続く箇所があった） | ABOUT 生成り → 写真の帯 → MENU 生成り → NEWS 白 → ACCESS 生成り → フッター黒 | 区切りが地色で分かる |
| ABOUT だけ見出しの作りが違った（小さな英字＋日本語の大見出し） | 他と同じ「英字の見出し＋日本語の添え字」に統一し、キャッチコピーは本文の頭に | 見出しだけ縦に読んで筋が通る |
| ACCESS の緑のボタン 2 つが配色から浮いていた。文言が「LINE 公式アカウント」で押すと何が起きるか分からない | 黒地に金の文字＋アイコン。「Uber Eats で注文する」「LINE で友だち追加」と動詞に | 配色の中に収まる |
| SP で営業時間の時間だけが次の行に落ち、間延びしていた | SP は曜日の下に時間、タブレット以上は横並び | 崩れなし |
| SP でページの最後まで下げると、固定の BGM ボタンがフッターの SNS に重なった | SP のフッターの下に固定ボタンの高さぶんの余白を取った。メニューは SP で 2 列にして縦の長さを詰めた | 重なりなし |

### 意図して残した例外
- メインビジュアルの大見出しは `clamp()`（画面幅に合わせて伸縮させるため段階に乗せない）
- 固定ボタン（BGM・PAGE TOP）とカードのホバーだけ影を残す。前者は「浮いている」こと、後者は「押せる」ことを示すため
- モーダルの閉じるボタンだけ丸（50%）。閉じるボタンだと一目で分かる形を優先

## CONTACT・プライバシーポリシー（ステップ 2-6）

| 部品 | 置き場 | 分けた理由 |
|---|---|---|
| `ContactForm` | `components/contact/` | 入力の確認と「送信済み」の表示の 2 つの状態を持つので、ページから切り出してクライアントコンポーネントにした。ページ本体（見出し・電話の窓口）はサーバーコンポーネントのまま |

- **送信先は持たない。**元テーマは Contact Form 7（プラグイン）。架空の店なので送信はせず、送信後に「作品のため実際には送信されない」と表示する。実際に使うなら、`onSubmit` の中を送信処理に差し替える
- 入力欄は `type`・`inputMode`・`autoComplete` を付け、スマホでメール・電話のキーボードに切り替わるようにした。入力欄の文字は 16px（iOS で入力時に画面が拡大されないため。段階の例外）
- エラーは欄の下に出し、`aria-invalid` と `aria-describedby` で読み上げにも伝える。送信を押したら、最初にエラーがある欄へフォーカスを移す
- 電話の窓口は黒い札にして、フォームより先に目に入る位置に置いた（予約は電話のほうが早いため）
- プライバシーポリシーの条文は `privacy.json` から出す。本文は 40 字前後で折り返す幅にした

## 写真の差し替え（ステップ 2-7）

- 写真は元サイトと同じフリー素材にした。メニューの写真は元サイトと同じ正方形なので、カードの比率を 4:3 から 1:1 に変えた（4:3 に切るとバンズの上が欠ける）。モーダルと写真の帯も同じ正方形の画像を使う
- 品目と説明文は写真に合わせて直した（架空のメニューなので、写真に無い具材を書かない）。サイドは写真のある 5 品にした
- 元の写真のうち、店名のロゴが写り込んでいるもの（ドリンクのカップ・グッズ・ポテトの包み紙）は使っていない
- ACCESS の案内図と OGP は `scripts/art/` の HTML から作る。架空の店なので、実在の地図は使わない

## グッズの写真（ステップ 2-8）

- 元サイトのグッズ写真（マグ・コースター・ボトル）には元の店名のロゴが入っているため使わない。Unsplash の、ロゴや文字の入っていない商品写真にした（出典は `docs/写真の出典.md`）
- 缶バッジとピンバッジは、見つかる写真がどれも他人のデザインや文字入りだったため、元サイトにもあったマグとボトルに替えた
- 品名と説明は写真に合わせた（無地の写真なので「ロゴキャップ」→「キャップ」など）。スマホのカード幅に 1 語で収まる長さにした
- LINEUP は品数が 6 つと少ないので、MENU より見出しの下とカードの間を広く取った（PC：縦 64px・横 48px）。カードの部品は MENU と共用のまま、並べ方だけ変えている
- グッズのカードは中の余白も広げた（PC 32px）。`MenuCard` に `roomy` を渡したときだけ広がるので、MENU のカードは変わらない
- 各ページの最後の区画は、フッターの手前を広めに取る（PC 168px・SP 96px）。`globals.scss` の `#main > .section:last-child` 1 か所で全ページに効く

## 余白と字間の見直し（ステップ 2-9）

- 全体が詰まって見え、高級感が出ていなかったため、値を引き上げた。余白の段階に `$sp-11`（160px）と `$sp-12`（240px）を足した
- 区画の上下：PC 120→160px・SP 64→96px。各ページの最後の区画はフッターの手前を PC 240px・SP 160px
- 本文：行間 1.8→2.0、字間 0.05em。英字見出しの字間 0.06→0.1em。日本語は全体で文節折り返し（`word-break: auto-phrase`）
- 見出しの下・メニューとNEWSの並びの間・カードの中の余白・カードの説明（12→13px）・フッターの上を、それぞれ 1 段ずつ広げた
- SCROLL の誘導は、下中央に文字と縦の線を置いた。線は薄い金で常に見せ、明るい金の光を上から下へ流す（横向きの線では下へ進むことが伝わらない。のびて消える線は点にしか見えない瞬間が長い。左下は MUSIC ON だけにして役割を分ける）

## 404 ページ（ステップ 2-10）

- 元テーマの `404.php` は「404」と出すだけだった。迷った人が次に進めるよう、大きな「404」・案内文・トップへの金ボタン・主なページ（MENU／GOODS／ACCESS／CONTACT）へのリンクを置いた
- リンクは `nav.json` のグローバルナビから TOP を除いたもの。ナビを直せば 404 のリンクもそろう
- 「404」の数字だけに使う特大の文字サイズ（SP 96px・PC 160px）を変数に足した。本文や見出しには使わない
- `robots: noindex` で検索エンジンに載せない
- 撮影スクリプトは、応答が 500 未満なら起動済みとみなす形に直した（404 のページも撮れるように）

## ダミーリンクの案内（ステップ 2-11）

- Instagram・LINE・Uber Eats は架空の店なので URL が `#`。そのままだと押すとページの先頭へ飛び、壊れているように見えるため、押してもページは動かさず、画面の下に「架空の店のため、リンク先はありません」と 2.5 秒出す
- `ExternalLink` 1 つにまとめ、ヘッダー・ドロワー・NEWS・ACCESS・フッターの 6 か所で使う。`store.json`／`nav.json` に本物の URL を入れれば、別タブで開く普通のリンクになる
- 案内は `DummyNotice`（`layout.tsx` に 1 つ）。`role="status"` で読み上げにも伝わる

## セキュリティ（ステップ 2-12）

- `next.config.ts` で全ページにセキュリティ用の応答ヘッダーを付ける（ファイルの種類を推測させない・他サイトの枠に入れさせない・参照元を最小限に・カメラ等を止める）。本番ビルドで 4 つとも付くことを確認
- 点検した結果：依存の脆弱性 0 件（`npm audit`）、鍵・トークンは作業ツリーにも履歴にも無し、`.env*` は Git の対象外、フォームは送信しない作り、`dangerouslySetInnerHTML` は固定の 1 行だけ
